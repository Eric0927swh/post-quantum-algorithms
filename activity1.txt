Activity 1: Explore PQC Algorithms
Post‑Quantum Cryptography (PQC) is designed to resist attacks from large‑scale quantum computers. This activity investigates NIST‑standardised post‑quantum signature algorithms and the ML‑KEM key encapsulation mechanism.

Step 2 ML‑KEM and comparison with RSA
What is ML‑KEM
ML‑KEM (formerly known as Kyber, defined in FIPS 203) is a NIST‑standardised Key Encapsulation Mechanism (KEM) based on the Module Learning‑With‑Errors (MLWE) lattice problem.
Instead of encrypting arbitrary user‑supplied plaintext, ML‑KEM works with two core functions:
Encaps (): Sender takes receiver’s public key, generates a random shared secret and a ciphertext.
Decaps (): Receiver uses its private key and incoming ciphertext to recover exactly the same shared secret.
This shared secret can then feed into symmetric encryption for secure session key exchange.
Differences between ML‑KEM and RSA
Post‑quantum security
RSA security builds on integer factorisation. A powerful quantum computer running Shor’s algorithm can break RSA completely.
ML‑KEM is built on the lattice MLWE hard problem, and it remains secure against known quantum‑computer attacks.
Core working paradigm
RSA‑OAEP is a public‑key encryption algorithm. Users can directly encrypt arbitrary plaintext data with the public key.
ML‑KEM is a key encapsulation mechanism. It automatically generates the shared secret internally. It cannot directly encrypt custom message payloads.
Typical parameter size (Security Level 1)
RSA‑2048: Public key 256 B, Private key 1218 B, Ciphertext 256 B
ML‑KEM‑512: Public key 768 B, Private key 1632 B, Ciphertext 768 B
Computational performance
ML‑KEM key‑generation, encapsulation and decapsulation are computationally fast, well‑suited for TLS and network‑level key negotiation.
RSA decryption is comparatively slow, especially for larger key lengths.
Available usage scope
RSA supports both data encryption and digital signature (RSA‑PSS).
ML‑KEM only handles key‑agreement. It cannot perform digital signatures; signing tasks require separate PQC signature families such as ML‑DSA.
